# برنامه‌ی اقدام — mahamprint.com

اولویت‌بندی بر اساس «اثر بر ترافیک ÷ ریسک اجرا». سایت زنده است، پس هر مورد با ملاحظات ایمنی آمده.

> **وضعیت (۱۷ آگوست ۲۰۲۶):** موارد ۱، ۲ و ۳ **انجام شدند** — ۲,۵۲۰ ریدایرکت و ریدایرکت `www`
> روی سرور فعال است. جزئیات در `DEPLOYED-CHANGES.md`. بقیه‌ی موارد هنوز باز است.

## ✅ انجام‌شده — بحرانی

### ۱. ریدایرکت ۳۰۱ آدرس‌های قدیمی (بزرگ‌ترین برد)

**اثر:** بازیابی بخش عمده‌ی ~۸۰۰ کلیک ماهانه‌ی از‌دست‌رفته
**ریسک:** پایین اگر نگاشت درست باشد — فقط افزودن قانون ریدایرکت، بدون دست‌زدن به داده

نگاشت کامل آماده است، در دو فایل:

**`data/redirect_map.csv`** — محصولات (۲,۴۵۵ آدرس ۴۰۴):

| اطمینان | تعداد | ایمپرشن | اقدام |
|---------|-------|---------|-------|
| `high` (≥ ۰.۵۵) | 2,293 | 236,295 | قابل اعمال پس از بازبینی نمونه‌ای |
| `medium` (۰.۳۵–۰.۵۵) | 98 | 9,952 | **بازبینی دستی الزامی** |
| `low` (۰.۲۰–۰.۳۵) | 17 | 270 | **بازبینی دستی الزامی** |
| `none` | 47 | — | به دسته‌ی مرتبط ریدایرکت شود |

**`data/redirect_map_taxonomy.csv`** — برند / دسته / تگ:

| بخش | نگاشت‌شده | نیازمند کار دستی |
|-----|-----------|-------------------|
| `/brand/` | 60 | 9 |
| `/category/` | 30 | 72 |
| `/tag/` | 0 | 261 |

**جمع آماده‌ی اعمال: ۲,۳۸۳ ریدایرکت که ۲۳۶,۲۹۵ ایمپرشن را پوشش می‌دهد.**
**نیازمند بازبینی دستی: ۵۰۴ مورد.**

> **اعتبارسنجی انجام شد:** ۲۵ مقصد تصادفی از دسته‌ی `high` محصولات و ۱۵ مقصد از
> نگاشت taxonomy تست شدند — **همه کد ۲۰۰ برگرداندند**، هیچ ریدایرکتی به ۴۰۴ نمی‌رود.

> ⚠️ در بازبینی نمونه دو تطبیق **اشتباه** پیدا شد:
> `Canon MF-232nw` → اشتباهاً `Canon MF656Cdw`
> `رول لیبل تک ردیفه` → اشتباهاً `دو ردیفه`
> هر دو در دسته‌ی medium/low بودند. **دسته‌ی high را هم نمونه‌گیری کنید.**
>
> توجه: اعتبارسنجی فقط تأیید می‌کند مقصد ۲۰۰ می‌دهد، نه اینکه **محصول درستی** است.
> درستیِ تطبیق فقط با نگاه انسانی یا نگاشت قطعی از دیتابیس قدیم تضمین می‌شود.

**قواعد الگویی (بدون نیاز به نگاشت تک‌به‌تک):**
```
/brand/<id>/<slug>      → /brands/<slug>          (اسلاگ برند حفظ شده)
/category/<id>/<slug>   → نگاشت دستی (۷۷ دسته، کار یک ساعته)
/tag/<id>/<slug>        → /products?search=<slug>  یا نزدیک‌ترین دسته
/index.php?productID=N  → نیاز به نگاشت N → محصول جدید
```

**نکته:** `/product/<id>/` شناسه‌ی عددی دارد ولی دیتابیس جدید cuid دارد و **فیلد legacy id ندارد**.
اگر در دیتابیس قدیم دسترسی دارید، جدول `id → title` را استخراج کنید تا نگاشت **قطعی** شود
به‌جای تطبیق متنی. این امن‌ترین مسیر است.

**اجرا:** فایل ریدایرکت nginx یا `next.config.js`. با nginx map ساده‌تر و سریع‌تر است:
```nginx
# /etc/nginx/conf.d/mahamprint-redirects.map
map $request_uri $redirect_target { ... }
```
قبل از reload حتماً `nginx -t` و از کانفیگ فعلی بکاپ بگیرید.

الان همه‌ی دسته‌های قدیمی به `/categories/printer` می‌روند. این soft-404 است و باید با نگاشت واقعی جایگزین شود.

### ۳. ریدایرکت www → non-www

`https://www.mahamprint.com/` الان ۲۰۰ می‌دهد. یک قانون ۳۰۱ در nginx:
```nginx
server_name www.mahamprint.com;
return 301 https://mahamprint.com$request_uri;
```
**ریسک:** بسیار پایین.

## بالا — تا دو هفته

### ۴. رفع کش (بزرگ‌ترین برد عملکردی)

هدر فعلی روی همه‌ی **صفحات HTML**:
```
cache-control: private, no-cache, no-store, max-age=0, must-revalidate
```

مسیرهای `/api/*` مشکلی ندارند — `next.config.ts` برایشان `s-maxage` درست تنظیم کرده و
روی سرور هم تأیید شد.

**آنچه تست شد و جواب نداد:** افزودن `export const revalidate = 300` به صفحه، **هیچ اثری
روی هدر ندارد**. روی build واقعی امتحان شد و هدر همچنان `no-store` ماند.

**علت واقعی:** `app/layout.tsx` و `app/(shop)/layout.tsx` مستقیماً Prisma صدا می‌زنند
(خواندن `storeSettings`). در App Router هر کار async کش‌نشده در layout آن را dynamic می‌کند،
و **layoutِ dynamic همه‌ی فرزندانش را dynamic می‌کند** — فارغ از تنظیم خود صفحه.

**راه‌حل درست:** همان کوئری‌های تنظیمات در layout ریشه کش شوند (`unstable_cache` یا
`use cache` در Next 16). چون تنظیمات سایت به‌ندرت عوض می‌شود، ریسکش پایین است.

**ریسک:** متوسط — این تغییر در ریشه‌ی سورس است و همه‌ی سایت‌ها را تحت تأثیر می‌گذارد.
بهتر است جدا از تغییرات دیگر و با یک دیپلوی مستقل انجام شود تا اگر مشکلی پیش آمد منشأش روشن باشد.
**نکته:** مسیرهای `/admin`, `/api`, `/user`, `/cart` باید `no-store` بمانند.

### ۵. رندر سمت سرور صفحه‌ی اصلی

صفحه‌ی اصلی الان ۰ لینک محصول و ۰ H1 در HTML دارد. ویجت‌ها باید SSR شوند
(صفحات دسته و برند از قبل درست کار می‌کنند — همان الگو را تکرار کنید).

همچنین:
- افزودن `<h1>` به صفحه‌ی اصلی
- عنوان از «مهام پرینت» به چیزی با کلمه‌ی کلیدی، مثلاً «مهام پرینت | خرید پرینتر، کارتریج و ماشین‌های اداری»
- کوتاه‌کردن توضیحات متا به ~۱۶۰ کاراکتر

### ۶. قیمت ۲۲۹۰ محصول بدون قیمت

**۸۳٪ کاتالوگ قیمت ندارد.** تا وقتی قیمت وارد نشده، در Product schema به‌جای `"price": 0`:
- یا کل بلوک `offers` حذف شود
- یا `availability` روی `https://schema.org/OutOfStock` یا `PreOrder` تنظیم شود

`price: 0` + `InStock` باعث رد شدن rich result می‌شود.

  این گزارش برای فعال‌کردن آن اشتباه بود.
- به‌جایش: تبدیل دسته‌ای تصاویر موجود به WebP (یک‌بار، خارج از سرور) و سرو کردن همان‌ها
- افزودن `width`/`height` به تصاویر برای جلوگیری از CLS
