برای روزی که اینترنت بین‌الملل قطع است و نه npm هست، نه GitHub، نه Let's Encrypt و نه Claude. همه‌چیز این صفحه بدون اینترنت باز می‌شود و کار می‌کند. بر پایه‌ی docs/guide/deployment.md و تجربه‌ی نصب uniqquestar و sezavar.

۰. همین امروز، تا اینترنت هست

هر چیزی که این‌جا تیک نخورد، روز قطعی جایگزین ندارد. تیک‌ها در همین مرورگر ذخیره می‌شوند.

چطور قطعی را روی سرور آزمایشی شبیه‌سازی کنم؟

۵. نصب سرور، قدم‌به‌قدم

برچسب‌ها نشان می‌دهند هر دستور کجا اجرا شود: روی لپ‌تاپ یا روی سرور. تیک هر قدم را بزنید.

۱دسترسی SSH بی‌رمز

روی لپ‌تاپ 
# اگر رمز روت منقضی است، اول یک بار با ssh عادی وارد شوید و عوضش کنید
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@{{IP}}
ssh -o BatchMode=yes root@{{IP}} 'echo ok'      # باید بدون رمز «ok» بدهد

# نام کوتاه (اختیاری) — بعد از این «ssh {{NAME}}» کافی است
cat >> ~/.ssh/config <<'EOF'

Host {{NAME}}
  HostName {{IP}}
  User root
  ServerAliveInterval 30
  ServerAliveCountMax 6
EOF
چرا مهم است: deploy.mjs با BatchMode=yes وصل می‌شود؛ بدون ورود بی‌رمز هیچ استقراری کار نمی‌کند. ServerAliveInterval هم جلوی قطع شدن نشست‌های طولانی روی شبکه‌ی ناپایدار را می‌گیرد.

۳پایه: منطقه‌ی زمانی، ساعت، swap، به‌روزرسانی خودکار

روی سرور 
# منطقه‌ی زمانی
timedatectl set-timezone Asia/Tehran

# swap چهارگیگی — بدون آن next build روی رم کم کشته می‌شود (کد ۱۳۷)
if ! swapon --show | grep -q /swapfile; then

systemctl disable --now unattended-upgrades apt-daily.timer apt-daily-upgrade.timer 2>/dev/null || true

ساعت سرور (حیاتی)

NTP پیش‌فرض اوبونتو خارجی است. ساعت غلط یعنی توکن ورود ادمین و کد OTP نامعتبر می‌شوند. اول NTP دیتاسنتر را از پشتیبانی بپرسید؛ بعد از نصب chrony (قدم ۵):

# جای NTP_SERVER آدرس NTP دیتاسنتر یا یک سرور داخلی که ساعتش درست است
echo "server NTP_SERVER iburst" > /etc/chrony/sources.d/local.sources
systemctl restart chrony && chronyc sources

# اگر هیچ NTP در دسترس نبود: دستی از روی ساعت لپ‌تاپ (روی لپ‌تاپ اجرا کنید)
ssh root@SERVER "date -s '$(date -u '+%Y-%m-%d %H:%M:%S') UTC'"

apt را به آینه‌ی داخلی ببرید (حالت ب)

# Ubuntu 24.04+ از قالب deb822 استفاده می‌کند

۴انتقال بسته به سرور

روی لپ‌تاپ

فقط بخش‌های لازم را بفرستید. rsync --partial اگر وسطش قطع شد، از همان‌جا ادامه می‌دهد — همان دستور را دوباره بزنید.

KIT=~/gardanos-offline-kit
ssh root@{{IP}} 'mkdir -p /root/kit/debs'
rsync -av --partial --progress $KIT/node $KIT/pm2 root@{{IP}}:/root/kit/
# فقط در حالت ج:
rsync -av --partial --progress $KIT/debs/{{UBU}} root@{{IP}}:/root/kit/debs/
# rsync روی سرور نیست؟ (خطای «rsync: command not found») ← اول با scp:
scp $KIT/debs/{{UBU}}/rsync_*.deb $KIT/debs/{{UBU}}/libpopt*.deb $KIT/debs/{{UBU}}/libxxhash*.deb \
    $KIT/debs/{{UBU}}/liblz4*.deb $KIT/debs/{{UBU}}/libzstd*.deb root@{{IP}}:/root/
ssh root@{{IP}} 'dpkg -i --skip-same-version /root/*.deb'
اتصال مستقیم لپ‌تاپ به سرور نیست یا مدام قطع می‌شود
  • پرش از یک سرور دیگر (مثلاً سرور mymonta که به هر دو دسترسی دارد): rsync -e "ssh -J mymonta" … و ssh -J mymonta root@{{IP}}.
  • تکه‌تکه برای فایل بزرگ روی خط ضعیف: 
    split -b 50M -d node_modules.tgz nm.part.        # لپ‌تاپ
rsync -av --partial nm.part.* root@{{IP}}:/root/kit/
ssh root@{{IP}} 'cd /root/kit && cat nm.part.* > node_modules.tgz && sha256sum node_modules.tgz'
sha256sum node_modules.tgz                        # لپ‌تاپ — دو عدد باید یکی باشند
  • از پنل دیتاسنتر: بعضی پنل‌ها آپلود فایل یا «ISO دلخواه» دارند؛ آخرین راه است.
  • VPN روی لپ‌تاپ را خاموش کنید؛ تجربه‌ی ۲.۴۳ و ۲.۴۷ نشان داد تونل VPN وسط انتقال و بیلد اتصال را می‌اندازد.

حالت ج (کاملاً آفلاین، از kit/debs)

به‌جای نصب کورکورانه‌ی همه‌ی .debها (که اگر نسخه‌ی سیستم تازه‌تر باشد خطای downgrade می‌دهد)، پوشه را یک مخزن محلی می‌کنیم تا apt خودش بهترین نسخه را انتخاب کند:

cd /root/kit/debs/{{UBU}}
apt-ftparchive packages . > Packages        # apt-utils روی اوبونتو سرور هست
echo "deb [trusted=yes] file:/root/kit/debs/{{UBU}} ./" > /etc/apt/sources.list.d/kit.list
APTKIT='-o Dir::Etc::sourcelist=/etc/apt/sources.list.d/kit.list -o Dir::Etc::sourceparts=- -o APT::Get::List-Cleanup=0'
apt-get $APTKIT update
DEBIAN_FRONTEND=noninteractive apt-get $APTKIT install -y nginx postgresql postgresql-contrib \
  redis-server rsync curl jq unzip ufw certbot chrony ca-certificates openssl
rm /etc/apt/sources.list.d/kit.list          # تا apt update بعدی سراغش نرود

# اگر apt-ftparchive نبود (آخرین راه — ترتیب را خودش درست می‌کند، دو بار بزنید):
dpkg -i --skip-same-version *.deb; dpkg -i --skip-same-version *.deb; dpkg --configure -a
نسخه‌ی اوبونتو باید با پوشه یکی باشد. debهای 24.04 روی 26.04 (و برعکس) خطای وابستگی می‌دهند. برای نسخه‌ی دیگر، قبل از قطعی UBUNTU_RELEASES="22.04" را هم بسازید.

۱۲nginx و SSL

روی سرور

برای اینکه nginx همیشه بالا بیاید، اول گواهی خودامضا می‌سازیم (با یا بدون اینترنت کار می‌کند). بعد اگر Let's Encrypt در دسترس بود جایش می‌نشانیم؛ اگر نبود، پشت CDN داخلی همین کافی است (بخش ۶).

mkdir -p /etc/ssl/{{NAME}} /var/www/letsencrypt/.well-known/acme-challenge
openssl req -x509 -nodes -newkey rsa:2048 -days 3650 \
  -keyout /etc/ssl/{{NAME}}/privkey.pem -out /etc/ssl/{{NAME}}/fullchain.pem \
  -subj "/CN={{DOMAIN}}" -addext "subjectAltName=DNS:{{DOMAIN}},DNS:www.{{DOMAIN}}"
chmod 600 /etc/ssl/{{NAME}}/privkey.pem
cat > /etc/nginx/sites-available/{{NAME}} <<'EOF'
# {{DOMAIN}} — فروشگاه گردانوس، pm2 «{{NAME}}» روی 127.0.0.1:{{PORT}}
server {
    listen 80;
    listen [::]:80;
    server_name {{DOMAIN}} www.{{DOMAIN}};

    # چالش ACME نباید ریدایرکت شود
    location ^~ /.well-known/acme-challenge/ {
        root /var/www/letsencrypt;
        default_type "text/plain";
    }
    location / { return 301 https://{{DOMAIN}}$request_uri; }
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name www.{{DOMAIN}};
    ssl_certificate     /etc/ssl/{{NAME}}/fullchain.pem;
    ssl_certificate_key /etc/ssl/{{NAME}}/privkey.pem;
    return 301 https://{{DOMAIN}}$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name {{DOMAIN}};

    ssl_certificate     /etc/ssl/{{NAME}}/fullchain.pem;
    ssl_certificate_key /etc/ssl/{{NAME}}/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 50m;     # آپلود عکس و فایل از پنل

    gzip on;
    gzip_vary on;
    gzip_types text/css application/javascript application/json image/svg+xml text/xml application/xml;

    location /_next/static/ {
        alias /var/www/{{NAME}}/.next/static/;
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    location /uploads/ {
        alias /var/www/{{NAME}}/public/uploads/;
        add_header Cache-Control "public, max-age=2592000";
        try_files $uri =404;
        access_log off;
    }

    location / {
        proxy_pass http://127.0.0.1:{{PORT}};
        proxy_http_version 1.1;
        # بدون Host درست، req.url در Next می‌شود localhost (باگ ۴۰۱ ترب)
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 300s;
        proxy_buffering off;          # پاسخ کلمه‌به‌کلمه‌ی دستیار هوشمند
    }
}
EOF
ln -sfn /etc/nginx/sites-available/{{NAME}} /etc/nginx/sites-enabled/{{NAME}}
rm -f /etc/nginx/sites-enabled/default          # فقط روی سرور تازه!
nginx -t && systemctl reload nginx
curl -sk -o /dev/null -w 'HTTP %{http_code}\n' --resolve {{DOMAIN}}:443:127.0.0.1 https://{{DOMAIN}}/
nginx 1.24 (اوبونتو 24.04) دستور http2 on; را نمی‌شناسد؛ برای همین listen 443 ssl http2 نوشته شده که روی هر دو نسخه کار می‌کند (روی 1.28 فقط هشدار می‌دهد). سرور مشترک: روی سروری که سایت دیگری دارد فقط reload، هرگز restart؛ و default را پاک نکنید.

اگر Let's Encrypt در دسترس است (حالت الف)

DNS دامنه باید به IP سرور اشاره کند و اگر پشت CDN است، مسیر چالش را رد کند:

۶. SSL بدون اینترنت جهانی

Let's Encrypt و تقریباً همه‌ی CAها بیرون از ایران‌اند. گواهی‌های فعلی ۹۰ روزه‌اند و در قطعی تمدید نمی‌شوند. گزینه‌ها به ترتیب پیشنهاد:

#روشمرورگر بازدیدکنندهکار لازم
۱CDN داخلی جلوی سایت (آروان/پارس‌پک) با گواهی لبه‌ی خودشان؛ بین CDN و سرور همان گواهی خودامضای قدم ۱۲قفل سبزدامنه را در CDN اضافه کنید، رکورد A را «پروکسی» کنید، حالت SSL مبدأ را روی «بدون اعتبارسنجی گواهی» (یا معادلش) بگذارید. این‌که CDN در قطعی بتواند گواهی لبه‌ی تازه صادر کند به CA خودش بستگی دارد — امروز دامنه‌ها را اضافه کنید تا گواهی‌شان از قبل صادر شده باشد.
۲گواهی Let's Encrypt که قبل از قطعی تمدید شدهقفل سبز تا انقضاچک‌لیست بخش ۰؛ حداکثر ۹۰ روز
۳گواهی تجاری یک‌ساله که از قبل خریده شدهقفل سبزفایل‌ها را جای /etc/ssl/NAME/ بگذارید و reload
۴فقط گواهی خودامضا، بدون CDNهشدار امنیتیفقط برای آزمون داخلی و پنل موقت؛ برای فروشگاه قابل‌قبول نیست
گواهی تمدیدنشده‌ی سایت‌های فعلی: وقتی تاریخ انقضا نزدیک شد و اینترنت هنوز قطع است، هر سایت را پشت CDN داخلی ببرید (گزینه‌ی ۱). nginx سرور با همان گواهی منقضی هم برای CDN کار می‌کند اگر اعتبارسنجی مبدأ خاموش باشد؛ یا جایش خودامضا بگذارید.
پشت CDN: nginx باید IP واقعی بازدیدکننده را بداند تا آمار شهرها و محدودیت تلاش ورود درست کار کند — هدر IP واقعی CDN را در nginx با set_real_ip_from و real_ip_header تنظیم کنید (IPهای CDN در پنل خودش). همچنین «کش» CDN را برای /api/ و /admin خاموش کنید. حافظه: بدنه‌ی پاسخ‌های ۴xx را CDN با صفحه‌ی خودش عوض می‌کند — آزمون خطا را از 127.0.0.1:PORT روی خود سرور بگیرید.
