## خلاصه‌ی هدر جدید

مشابه هدر پیش‌فرض است (لوگو، جستجو، مگامنو، حساب کاربری، علاقه‌مندی، سبد خرید)
با سه تفاوت اصلی:

**۱) پس‌زمینه‌ی شیشه‌ای و شفاف**
هدر در جریان صفحه می‌ماند (محتوا زیرش پنهان نمی‌شود) اما پس‌زمینه‌اش شفاف‌تر و
بلورتر از هدر پیش‌فرض است. با اسکرول، شفافیت و شدت بلور به مقادیر «حالت اسکرول»
تغییر می‌کند و یک سایه‌ی ملایم اضافه می‌شود. رنگ متن و آیکن‌ها بر اساس حالت
روز/شب سایت عوض می‌شود.

**۲) نوار جستجوی موبایل با انیمیشن morph**
در موبایل هدر ابتدا دو ردیفه است: ردیف اول (همبرگری، لوگو، آیکن‌ها) و ردیف دوم
یک کادر جستجوی تمام‌عرض. در این حالت آیکن ذره‌بین در ردیف اول نمایش داده
نمی‌شود. با اسکرول، کادر جستجو هم‌زمان جمع، کوچک و به سمت آیکن‌ها منتقل می‌شود
و در همان لحظه آیکن ذره‌بین در ردیف اول باز می‌شود؛ نتیجه یک هدر یک‌ردیفه است.
برگشت به بالای صفحه انیمیشن را معکوس اجرا می‌کند.

**۳) جمع‌شدن ردیف منو در دسکتاپ (auto-hide جهت‌دار)**
در دسکتاپ هدر دو ردیفه است: ردیف اول (لوگو، جستجو، آیکن‌ها) و ردیف دوم مگامنو.
با اسکرول **رو به پایین** ردیف منو جمع می‌شود و فقط ردیف اول می‌ماند؛ با اسکرول
**رو به بالا** یا رسیدن به نزدیکی بالای صفحه دوباره باز می‌شود. ردیف اول همیشه
sticky و در دسترس است.

## ۱ — رجیستری هدرها و مفهوم `scope`

`registry.ts` تنها منبع حقیقت برای لیست هدرهاست. دو چیز به آن اضافه شد:

### واریانت `GLASS`

```ts
{
  id: "GLASS",
  label: "هدر شفاف (شیشه‌ای)",
  overlay: false,
  scope: "site",
}
```

### فیلد `scope`

قبلاً فرض ضمنی این بود که انتخاب هدر «فقط برای صفحه اصلی» است. حالا هر واریانت
دامنه‌ی اعمال خودش را اعلام می‌کند:

- `scope: "site"` — روی همه‌ی صفحات (`DEFAULT`, `GLASS`)
- `scope: "home"` — فقط صفحه اصلی، بقیه صفحات هدر پیش‌فرض می‌گیرند (`UNIQUE_STAR`)

به این ترتیب **فیلد جدیدی به دیتابیس اضافه نشد** و همان `homeHeaderVariant`
به‌عنوان انتخابگر واحد هدر سایت استفاده می‌شود. اضافه‌کردن هدر بعدی فقط یک
رکورد در همین آرایه است.

### تنظیمات ظاهری

نوع `GlassHeaderConfig` و توابع `normalizeGlassConfig()` / `hexToRgbChannels()`
هم اینجا تعریف شده‌اند تا ادمین، API و کامپوننت هر سه از یک منبع استفاده کنند:

| کلید | معنی | بازه |
|---|---|---|
| `opacityTop` | شفافیت پس‌زمینه در بالای صفحه | ۰ تا ۱۰۰ |
| `opacityScrolled` | شفافیت پس‌زمینه بعد از اسکرول | ۰ تا ۱۰۰ |
| `blurTop` | شدت بلور در بالای صفحه | ۰ تا ۴۰ px |
| `blurScrolled` | شدت بلور بعد از اسکرول | ۰ تا ۴۰ px |
| `tintLight` / `tintDark` | رنگ تینت پس‌زمینه (روز / شب) | hex |
| `textLight` / `textDark` | رنگ متن و آیکن‌ها (روز / شب) | hex |
| `showBorder` | نمایش خط حاشیه‌ی پایین هدر | boolean |

`normalizeGlassConfig()` هر ورودی نامعتبری را به مقدار پیش‌فرض برمی‌گرداند
(عدد خارج از بازه، رنگ بدون فرمت `#rrggbb`، `null`، آبجکت ناقص) و هم در سمت
سرور و هم در فرم ادمین صدا زده می‌شود.

مقادیر پیش‌فرض: شفافیت ۳۵٪ / ۵۵٪، بلور ۱۰px / ۲۴px، تینت `#ffffff` / `#050505`،
متن `#1f2937` / `#f3f4f6`، حاشیه روشن.

## ۲ — کامپوننت هدر شیشه‌ای

`components/layout/headers/GlassHeader.tsx`

### چرا رنگ‌ها با CSS سوییچ می‌شوند و نه با `useTheme()`

`ThemeProvider` مقدار اولیه‌اش `"light"` است و حالت واقعی را داخل `useEffect`
از `localStorage` می‌خواند. اگر رنگ هدر از روی `theme` ساخته می‌شد، در بارگذاری
اول در حالت شب یک فریم روشن دیده می‌شد.

به‌جای آن، تمام رنگ‌ها به‌صورت متغیر CSS ست می‌شوند و سوییچ روز/شب با کلاس
`.dark` روی `<html>` انجام می‌شود — همان کلاسی که اسکریپت inline در
`app/layout.tsx` قبل از اولین رنگ‌آمیزی می‌گذارد. نتیجه: بدون flash.

```css
.ghd-root      { --ghd-tint: var(--ghd-tint-light); --ghd-text: var(--ghd-text-light) }
.dark .ghd-root{ --ghd-tint: var(--ghd-tint-dark);  --ghd-text: var(--ghd-text-dark) }
```

`useTheme()` فقط برای دکمه‌ی تغییر حالت نمایش (`toggle`) استفاده می‌شود.

### چرا inline style فقط مقادیر «ورودی» را ست می‌کند

متغیرهای فعال (`--ghd-alpha`, `--ghd-blur`) در CSS از روی مقادیر ورودی مشتق
می‌شوند و قانون `[data-scrolled="true"]` آن‌ها را عوض می‌کند:

```css
.ghd-root                        { --ghd-alpha: var(--ghd-alpha-top) }
.ghd-root[data-scrolled="true"]  { --ghd-alpha: var(--ghd-alpha-scrolled) }
```

اگر `--ghd-alpha` مستقیم در `style` کامپوننت ست می‌شد، **inline style بر هر
قانون CSS غالب است** و حالت اسکرول هیچ‌وقت اعمال نمی‌شد. به همین دلیل inline
فقط `--ghd-alpha-top`, `--ghd-alpha-scrolled`, `--ghd-blur-*`, رنگ‌ها و
`--ghd-border-alpha` را می‌دهد.

### انیمیشن morph جستجوی موبایل

دو انیمیشن هم‌زمان با یک منبع (`data-scrolled` روی ریشه‌ی هدر):

```css
.ghd-searchrow { height: 3.75rem; transform-origin: left center }
.ghd-root[data-scrolled="true"] .ghd-searchrow {
  height: 0; opacity: 0; transform: scale(.55) translateY(-14px);
}
.ghd-searchbtn { width: 0; opacity: 0; transform: scale(.4); pointer-events: none }
.ghd-root[data-scrolled="true"] .ghd-searchbtn {
  width: 2.75rem; opacity: 1; transform: scale(1); pointer-events: auto;
}
```

- `transform-origin: left center` — چون صفحه RTL است، گروه آیکن‌ها سمت چپ
  فیزیکی قرار دارد؛ نوار جستجو به همان سمت جمع می‌شود تا حس «تبدیل شدن به آیکن»
  بدهد.
- آستانه‌ی اسکرول `window.scrollY > 40` با listener از نوع `passive`.
- هر دو انیمیشن `cubic-bezier(.4,0,.2,1)` با مدت ۰٫۴۵ ثانیه‌اند و آیکن با
  ۱۲۰ms تأخیر ظاهر می‌شود تا حرکت پیوسته دیده شود.
- بلوک `@media (prefers-reduced-motion: reduce)` انیمیشن‌ها را برای کاربرانی
  که کاهش حرکت را فعال کرده‌اند خاموش می‌کند.

### منوی دسکتاپ

`HeaderMenu` بدون تغییر استفاده می‌شود؛ فقط داخل `<div className="ghd-nav">`
قرار گرفته و یک قانون CSS پس‌زمینه‌ی خودش را شفاف می‌کند تا شیشه‌ای بودن هدر
شکسته نشود:

```css
.ghd-nav > nav { background: transparent; border-top: 1px solid var(--ghd-border) }
```

این کار عمداً به‌جای افزودن prop به `HeaderMenu` انجام شد تا هدر پیش‌فرض دست
نخورد.

### جمع‌شدن ردیف منو با اسکرول (دسکتاپ)

منبع این انیمیشن `data-navhidden` روی ریشه‌ی هدر است — جدا از `data-scrolled`،
چون معیارشان فرق دارد: `data-scrolled` فقط به «چقدر پایین آمده‌ایم» نگاه می‌کند،
`data-navhidden` به **جهت** اسکرول.

```css
@media (min-width:1024px){
  .ghd-nav{ height: var(--ghd-navrow-h); opacity: 1;
            transition: height .4s cubic-bezier(.4,0,.2,1), opacity .25s ease }
  .ghd-nav.ghd-nav-clip{ overflow: hidden }
  .ghd-root[data-navhidden="true"] .ghd-nav{ height: 0; opacity: 0; pointer-events: none }
}
```

منطق در `onScroll`:

| وضعیت | نتیجه |
|---|---|
| `scrollY <= 90` (نزدیک بالای صفحه) | منو همیشه باز |
| جابه‌جایی کمتر از `6px` | نادیده گرفته می‌شود (ضدلرزش) |
| اسکرول رو به پایین | `navHidden = true` |
| اسکرول رو به بالا | `navHidden = false` |

سه نکته‌ی پیاده‌سازی که اگر دست بزنید مهم‌اند:

- **ارتفاع با `ResizeObserver` اندازه‌گیری می‌شود**، نه عدد ثابت. محتوای
  `HeaderMenu` با `fetch` می‌آید و ارتفاع نوار قبل و بعد از لود فرق می‌کند؛
  مقدار اندازه‌گیری‌شده در `--ghd-navrow-h` می‌نشیند (تا وقتی صفر است `auto`
  می‌ماند تا منو در بدترین حالت هم دیده شود). زیر `lg` عنصر `display:none` است
  و همین observer وقتی دوباره نمایان شود مقدار درست را می‌دهد.
- **`overflow:hidden` دائمی نیست.** مگامنو `absolute` است و زیر نوار باز
  می‌شود؛ اگر ظرف همیشه کلیپ می‌شد مگامنو بریده می‌شد. پس کلاس `ghd-nav-clip`
  فقط در حالت جمع‌شده و تا ۴۵۰ms بعد از هر تغییر (طول انیمیشن) اضافه می‌شود.
- **آستانه‌ی جهت** جدا از آستانه‌ی `scrolled` است؛ `90px` انتخاب شد تا نوار
  درست بعد از رد کردن ارتفاع ردیف اول جمع شود، نه زودتر.

## ۳ — اتصال به سایت

`HeaderSwitcher.tsx` حالا سه حالت دارد:

```
isHome && UNIQUE_STAR  →  UniqueStarHeader   (scope: home)
GLASS                  →  GlassHeader        (scope: site — همه‌ی صفحات)
سایر                    →  هدر پیش‌فرض
```

`Header.tsx` (سرور کامپوننت) مقدار `headerGlassConfig` را از `StoreSettings`
می‌خواند، با `normalizeGlassConfig()` امن می‌کند و به `HeaderSwitcher`
می‌دهد. اگر خواندن تنظیمات شکست بخورد، `null` می‌رود و کامپوننت خودش مقادیر
پیش‌فرض را می‌گذارد.

## ۴ — تنظیمات ادمین

مسیر: **ادمین ← تنظیمات سایت ← تب «هدر سایت»** (نام قبلی تب: «هدر صفحه اصلی»).

- هر کارت هدر یک برچسب دامنه دارد: «کل سایت» (سبز) یا «فقط صفحه اصلی» (آبی).
- با انتخاب «هدر شفاف (شیشه‌ای)» کارت **تنظیمات ظاهری هدر شیشه‌ای** ظاهر می‌شود:
  - چهار اسلایدر: شفافیت و بلور، هرکدام برای دو حالت «بالای صفحه» و «بعد از اسکرول».
  - چهار انتخابگر رنگ (تینت و متن، برای روز و شب) با ورودی hex در کنارشان.
  - سوییچ نمایش خط حاشیه‌ی پایین.
  - دکمه‌ی «بازگرداندن به مقادیر پیش‌فرض».
- **پیش‌نمایش زنده**: چهار کادر (بالای صفحه/بعد از اسکرول × روز/شب) که همان
  فرمول رنگ کامپوننت را روی یک پس‌زمینه‌ی رنگی نمونه اجرا می‌کنند، تا اثر
  شفافیت و بلور بدون ذخیره‌کردن دیده شود.

### اصلاح جانبی

کارت «منوی کشویی (همبرگری)» به‌اشتباه **داخل** شرط نمایش `hint` تودرتو شده بود،
یعنی فقط وقتی دیده می‌شد که هدر انتخاب‌شده `hint` داشت (عملاً فقط یونیک استار).
ساختار JSX اصلاح شد و این کارت حالا همیشه نمایش داده می‌شود.

## ۵ — دیتابیس و API

### Prisma

```prisma
model StoreSettings {
  homeHeaderVariant String  @default("DEFAULT")
  mobileMenuGlass   Boolean @default(false)
  headerGlassConfig Json?          // ← جدید
}
```

مایگریشن: `prisma/migrations/20260814091412_add_header_glass_config/`

`Json?` انتخاب شد چون همه‌ی تنظیمات ظاهری این هدر یک واحد منطقی‌اند و افزودن
کلید جدید در آینده مایگریشن نمی‌خواهد. `null` بودن مقدار = استفاده از
پیش‌فرض‌ها.

### API

`PUT /api/admin/site-settings`

```ts
if (data.homeHeaderVariant !== undefined)
  updateData.homeHeaderVariant = normalizeVariant(data.homeHeaderVariant);
if (data.headerGlassConfig !== undefined)
  updateData.headerGlassConfig = normalizeGlassConfig(data.headerGlassConfig);
```

دو نکته:

- `homeHeaderVariant` حالا از `normalizeVariant()` رد می‌شود؛ قبلاً هر رشته‌ای
  مستقیم ذخیره می‌شد.
- یک بلوک تکراری `homeHeaderVariant` که دو بار پشت سر هم نوشته شده بود حذف شد.

## ۶ — مشکلاتی که حین تست پیدا و برطرف شد

### الف) هدر در حالت شب روشن دیده می‌شد

در `globals.css` رنگ `body` همیشه سفید است و رنگ تیره‌ی صفحه فقط روی `<main>`
اعمال می‌شود — و `<main>` **زیر** هدر شروع می‌شود. بنابراین در بالای صفحه،
`backdrop-filter` هدر روی سفید محاسبه می‌شد و ۳۵٪ تینت تیره روی سفید،
خاکستری روشن می‌داد.

چون هدر پیش‌فرض شفافیت ۸۰٪ دارد، این مشکل در آن به چشم نمی‌آمد.

راه‌حل، بدون دست‌زدن به استایل سراسری، یک قانون محدود به همین هدر است:

```css
html body:has(.ghd-root)      { background-color: #f3f4f6 }
html.dark body:has(.ghd-root) { background-color: #050505 }
```

این قوانین فقط تا وقتی روی صفحه‌اند که هدر شیشه‌ای رندر شده باشد و رنگ‌ها دقیقاً
همان رنگ `<main>` هستند، پس هیچ تغییر بصری دیگری ایجاد نمی‌کنند.

### ب) سرریز افقی صفحه بعد از اسکرول در موبایل

با ظاهر شدن آیکن جستجو در ردیف اول، مجموع عرض آیتم‌ها در عرض ۳۹۰px از فضای
موجود بیشتر می‌شد و کل صفحه حدود ۵۰px به‌صورت افقی سرریز می‌کرد (نوار پایین
موبایل بریده می‌شد).

اصلاحات:

- فاصله‌ها در موبایل کم شد: `gap-2 md:gap-8` بین گروه‌ها و `gap-2 md:gap-3`
  داخل گروه آیکن‌ها.
- ارتفاع لوگو در موبایل `h-8` با `max-w-[100px]` (در دسکتاپ `h-10`).
- پدینگ دکمه‌ها در موبایل کمتر شد و `flex-shrink-0` روی آیتم‌های ثابت گذاشته شد.
- `overflow-x: clip` روی ریشه‌ی هدر به‌عنوان محافظ. عمداً `clip` و نه `hidden`،
  چون `clip` روی یک محور اجازه می‌دهد محور دیگر `visible` بماند و پنل نتایج
  جستجو بتواند از پایین هدر بیرون بزند.

## تست انجام‌شده

`tsc --noEmit` بدون خطا. اسکرین‌شات هر چهار حالت روی صفحه‌ی واقعی گرفته و بررسی
شد:

| حالت | نتیجه |
|---|---|
| موبایل ۳۹۰px — بالای صفحه، شب | دو ردیفه، جستجوی تمام‌عرض، پس‌زمینه‌ی تیره‌ی شیشه‌ای ✓ |
| موبایل ۳۹۰px — اسکرول‌شده، شب | یک ردیفه، آیکن ذره‌بین، بدون سرریز افقی ✓ |
| موبایل ۳۹۰px — بالای صفحه، روز | دو ردیفه، شیشه‌ای روشن، متن تیره ✓ |
